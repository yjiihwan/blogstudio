# voice-dna — 톤 DNA 적용

글 전체의 말투·어조·인칭·리듬을 하나의 **톤 DNA**로 통일한다.
톤의 출처는 두 갈래이며, **분기 규칙이 이 스킬의 핵심**이다.

> 벤치마크: `az9713/ai-co-writing-claude-skills`(voice-dna-creator) — 샘플 3~10개를 분석해
> **재현 가능한 구조화 JSON 프로필**(톤 가이드·문장/문단 템플릿·어휘·오프닝/클로징·never-use 목록·
> 채널별 변형)로 코드화한다. 우리는 이 "구조화 프로필" 개념을 **우리 분기(사용자입력/페르소나추정)에
> 얹어** 재설계한다. 공개팩은 사람의 과거 글 샘플로 프로필을 만들지만, 우리는 (a) 사용자 톤 지시 또는
> (b) 페르소나 데이터에서 프로필을 뽑는다는 점이 다르다.

## 트리거 (언제 발동)

- storytelling·anti-ai를 거쳐 구조·정제가 끝난 뒤(톤은 구조 확정 후 적용).
- 문단마다 말투(격식·인칭·어미)가 들쭉날쭉할 때.
- 페르소나의 브랜드 보이스와 실제 어조가 어긋날 때.

## 톤 결정 분기 규칙 (필수 — 이 스킬의 정체성)

```
IF 사용자가 톤 관련 입력을 넣었으면:
    → (a) 사용자 톤 입력을 최우선으로 따른다. 페르소나와 충돌해도 사용자 입력 우선.
ELSE (톤 입력이 없으면):
    → (b) 페르소나 입력 데이터로 톤을 자동 추정해 조정한다.
```

- **(a) 사용자 톤 입력 우선**: `options.toneInstruction`(예: "친근하고 유쾌하게", "차분한 전문가 톤",
  "20대에게 반말 섞어")이 있으면 그것을 최상위 규칙으로 삼는다. 페르소나 `brandVoice`/`formality`와
  충돌하면 **사용자 지시를 따르고** `notes`에 "페르소나 기본 톤과 다른 사용자 지정 톤 적용됨"을 남긴다.
- **(b) 페르소나 자동 추정**: 톤 입력이 없으면 §추출 명세대로 `PersonaInput` 필드에서 프로필을 뽑는다.

두 경로 모두 최종 산출은 **동일한 Voice DNA 구조화 프로필**이다(아래). 차이는 프로필을 채우는 근거뿐.

## 페르소나 자동 추정 — 추출 명세 (무엇을, 무엇에서)

톤 입력이 없을 때, 아래 표대로 **각 프로필 항목을 어떤 페르소나 필드에서 도출하는지**를 고정한다.

| 프로필 항목 | 근거 필드(우선순위) | 추출 규칙 |
|---|---|---|
| 격식/어미 | `formality`(informal/neutral/formal) | informal→"~해요/~죠", neutral→"~합니다/~다" 혼용, formal→"~습니다" |
| 인칭/시점 | `pointOfView`(first/third/expert) | first→"저는/제가", third→관찰서술, expert→"~을 권합니다" 단정 |
| 어휘 밀도·전문성 | `niche`(업종) | 피트니스=활력·직접적, 의료=신중·단정 회피, 뷰티=감각·경험담 |
| 호칭·예시·리듬 | `audience`·`ageGroup`·`gender` | 20대→짧은 호흡·구어체 허용, 40대→차분·근거 중심 |
| 어조 무게 | `purpose`(정보/설득/후기) | 정보=중립, 설득=능동 권유, 후기=1인칭 경험체 |
| 1차 보이스 | `brandVoice` | 명시돼 있으면 위 모든 항목의 상위 가이드로 우선 |

- `brandVoice`가 있으면 그것을 1차 근거로 삼고, 나머지 필드로 세부를 채운다.
- 추정 결과를 한 줄로 요약해 `notes`에 남긴다(예: "추정 톤: 40대 여성 타깃·중립격식·1인칭 후기체").

## 산출물 — Voice DNA 구조화 프로필 (핵심 추가)

두 경로 모두 아래 JSON 프로필을 **먼저 확정한 뒤** 그 프로필대로 본문을 물들인다. 프로필은 `notes` 또는
별도 필드로 검수 화면에 노출해, 이후 글에도 재사용(재현)할 수 있게 한다.

```json
{
  "source": "user | persona",          // (a)인지 (b)인지
  "summary": "40대 여성 타깃·중립격식·1인칭 후기체",
  "tone": { "formality": "neutral", "warmth": "따뜻함-중", "directness": "중" },
  "person": { "pov": "first_person", "reader_address": "구독자님/여러분 대신 '~하시는 분'" },
  "sentence": { "avg_len": "짧게-중간 혼합", "ending_mix": ["~다", "~죠", "명사종결"] },
  "lexicon": { "prefer": ["직접 겪은", "실제로"], "domain_terms": "피트니스 용어 최소 설명 후 사용" },
  "opening": "구체 장면 또는 독자 문제로 진입(인사·자기소개 금지)",
  "closing": "정리 상투 대신 여운/행동 제안 1문장",
  "never_use": [
    "오늘은 ~알아보겠습니다", "도움이 되셨길 바랍니다",
    "정말/너무/매우 떡칠", "다양한/효과적인", "여러분!"
  ],
  "channel_variants": {
    "blog": "기본 프로필 그대로(본 스튜디오 기본 채널)",
    "instagram": "문장 더 짧게·1~2문단·해시태그 2~3개",
    "naver_place": "정보 밀도↑·과장 배제·리뷰 톤"
  }
}
```

- **never_use 목록**: anti-ai 카탈로그와 연동한다. voice-dna는 톤을 입히면서 이 목록을 재유입시키지
  않는 게 의무다(아래 DON'T). 사용자 톤 지시가 특정 표현을 요구하면 그 항목은 목록에서 뺀다.
- **channel_variants**: 블로그 스튜디오 기본 채널은 `blog`. 다른 채널로 리퍼포징할 때 프로필을
  통째로 다시 만들지 않고 변형만 적용하도록 미리 정의(공개팩의 channel-specific variants 개념).

## 규칙

### DO
- 먼저 **Voice DNA 프로필을 확정**하고, 그 프로필(어미·인칭·리듬·호칭·오프닝/클로징)을 글 전체에 일관 적용.
- 페르소나 `formality`/`pointOfView` 범위를 (a)의 사용자 지시가 없을 땐 지킨다.
- 톤에 맞는 어휘로 바꾸되 의미·사실은 유지한다.
- 프로필의 `never_use`를 준수하고, 위반이 발견되면 그 표현을 톤에 맞는 대체로 교체.

### DON'T
- 톤을 맞추려고 없는 경험·감정·사실을 지어내지 않는다(전역 0번 규칙).
- **anti-ai가 제거한 패턴(강조 부사 떡칠·번역투)을 톤이라는 명목으로 되살리지 않는다**(never_use 위반).
- 상호·이미지 마커·확정 수치를 톤 때문에 변형하지 않는다.
- 사용자 톤 입력이 있는데 페르소나 기본값으로 덮어쓰지 않는다(분기 위반).
- 채널 변형을 요청받지 않았는데 기본 `blog` 프로필을 다른 채널 톤으로 바꾸지 않는다.

## 적용 전후 예시

**예시 A — 사용자 톤 입력 있음** (`toneInstruction: "20대에게, 가볍고 솔직하게"`)
- 전: "본 시설은 최신 웨이트 기구를 완비하고 있습니다."
- 후: "여기 웨이트존, 기구 상태 진짜 괜찮음. 대기 안 걸리고 바로 씀."
- (프로필 source=user, never_use에서 "진짜"는 사용자 지시상 허용으로 제외)

**예시 B — 톤 입력 없음, 페르소나 자동 추정** (`formality: formal`, `pointOfView: expert`, `niche: 의료`)
- 전: "이거 진짜 효과 좋아요!! 꼭 받아보세요~"
- 후: "해당 시술은 개인차가 있으며, 상담을 통해 적합 여부를 확인하는 것을 권합니다."
- (프로필 source=persona, summary="의료·formal·expert·단정 회피")

## 통과 체크리스트

- [ ] Voice DNA 프로필(JSON)이 먼저 확정돼 `notes`/필드에 노출됐다.
- [ ] 사용자 톤 입력이 있으면 그것이 최우선 적용됐고(source=user), 페르소나 충돌 시 `notes`에 기록됐다.
- [ ] 톤 입력이 없으면 §추출 명세대로 추정된 톤이 `notes`에 한 줄로 명시됐다(source=persona).
- [ ] 어미·인칭·호칭이 글 전체에서 일관된다(프로필과 일치).
- [ ] `never_use` 표현 재유입 0개(anti-ai 정합).
- [ ] 톤 맞춤 과정에서 새로 지어낸 사실 0개.
- [ ] 채널 변형은 요청된 채널에 한해서만 적용됐다.

## 입출력 (엔진 배선)

```ts
// 입력
{ draftMd, persona, options?: {
    toneInstruction?: string;                 // 있으면 분기 (a), 없으면 (b) 자동추정
    channel?: "blog" | "instagram" | "naver_place"; // 기본 blog
} }
// 출력
{ revisedMd, changes,
  profile: VoiceDnaProfile,   // 위 JSON 구조. 재사용 위해 항상 반환
  notes: string[]             // 필수: source(user/persona)·요약 1줄
}
```

> 분기 요약: **`options.toneInstruction`이 비어있지 않으면 (a) 사용자 우선, 비어있으면 (b) 페르소나
> 자동 추정.** 두 경로 모두 **동일 구조의 Voice DNA 프로필**을 산출하며, 판정·프로필은 항상 `notes`/
> `profile`로 검수 화면에 노출한다.
