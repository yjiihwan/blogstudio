# anti-ai — 'AI 티' 걷어내기

기계가 쓴 티가 나는 패턴을 제거해, 사람이 직접 쓴 글의 결로 되돌린다.
`DEFAULT_GLOBAL_GUIDE`(global-guide.ts)의 규칙을 **독립 재작성 패스**로 집행한다.

> 벤치마크: `conorbronsdon/avoid-ai-writing`(영어, 패턴 ~51개/6카테고리·교체테이블 109개·3모드·2차패스).
> 이 문서는 그것을 **번역이 아니라 한글 블로그용으로 재설계**했다. 영어 관용구(em-dash·"It's not X, it's Y"·
> utm_source=chatgpt.com 등)는 한글 글에서 드물거나 무의미하므로, 한국어 AI 문체에서 실제로 튀는
> 신호로 카테고리를 다시 짰다.

## 트리거 (언제 발동)

- 초안·storytelling 결과에 아래 신호가 하나라도 있을 때(상세 패턴은 §패턴 카탈로그).
- 파이프라인상 **storytelling 직후** 상시 실행(연결 접속사 남발을 정리하기 위해).

## 동작 모드 3가지 (options.mode)

| 모드 | 기능 | 언제 |
|---|---|---|
| **rewrite**(기본) | 감지 → 재작성 → **2차 패스 자가감사** → 4섹션 출력 | 일반 자동 파이프라인 |
| **detect** | 재작성 없이 플래그만. 각 히트에 심각도 P0/P1/P2 부여 | "검수만/스캔"(반자동 화면 진단) |
| **edit** | 원문 최소 변경(제자리 편집)·구조 유지, 변경 리포트 첨부 | 사용자가 완성 원고를 넘겨 부분만 손볼 때 |

## 2단계 감지 (핵심 — 1차 → 2차 패스)

1. **1차 패스(감지·재작성)**: 아래 카탈로그로 초안을 훑어 히트를 심각도별로 플래그하고 rewrite 모드면 교체.
2. **2차 패스(자가감사)**: **재작성한 결과물을 다시 스캔**한다. 재작성이 새로 만든 AI티(예: 부사 하나 지웠더니
   다른 부사 삽입, 접속사 정리하다 다른 접속사 남발)를 잡는다. 2차에서 P0/P1이 남으면 그 부분만 재교체.
   2차까지 통과해야 완료. (공개팩의 second-pass audit에 해당.)

## 심각도 (P0/P1/P2)

- **P0 (차단)**: 그대로 나가면 즉시 'AI가 썼다'가 들통나는 신호. 반드시 제거. 상투 도입/마무리,
  "~할 수 있습니다" 3회+ 반복, 종결어미 4연속 동일, rule-of-three 강박, 이모지 헤더.
- **P1 (강권)**: 어색하고 기계적. 특별한 사유 없으면 교체. 강조부사 떡칠, 막연 수식어("다양한/효과적인"),
  접속사 문두 남발, 과한 명사화, 균일 문장길이.
- **P2 (권고)**: 있으면 다듬는 게 낫지만 문맥상 허용될 수 있음. 괄호 완화("~인 것 같습니다"), 습관적 병렬
  ("먼저/또한/마지막으로"), 과한 볼드.

전면 재작성 임계값(공개팩 차용): **P0 1개 이상 OR (P1 5개+ AND 3개 카테고리+)** → 문장 교체가 아니라
문단 단위 재작성으로 승격.

## 패턴 카탈로그 (6카테고리 · 한글 특화)

### A. 상투 문구 / 정형구 (P0·P1)
1. 상투 도입 "오늘은 ~에 대해 알아보겠습니다 / 소개해 드리겠습니다" (P0)
2. 상투 마무리 "도움이 되셨길 바랍니다 / 지금까지 ~였습니다 / 참고하시기 바랍니다" (P0)
3. 자문자답 소제목 "○○란? / ○○의 장점 / ○○, 왜 중요할까?" 반복 (P1)
4. 공허한 일반론 "건강은 중요합니다 / 요즘 ~가 대세입니다 / 삶의 질을 높여줍니다" (P1)
5. "여러분"·"~하시는 분들"·"~을 고민하고 계신가요?" 호명 상투 (P1)
6. rule-of-three 강박(무엇이든 3개로 묶기: "빠르고, 편하고, 확실하게") (P1)

### B. 어휘 / 표현 (P1·P2) — §교체 테이블과 연동
7. 막연 수식어 남발 "다양한 / 여러 가지 / 각종 / 폭넓은 / 전반적인" (P1)
8. 공허 형용사 "효과적인 / 중요한 / 특별한 / 완벽한 / 최적의 / 뛰어난" (P1)
9. 강조부사 떡칠 "정말 / 너무 / 진짜 / 매우 / 굉장히 / 상당히 / 무척" (P1)
10. "~할 수 있습니다 / ~라고 할 수 있습니다 / ~중 하나입니다" 번역투 반복 (P0 3회+ / P1)
11. 과한 명사화 "~의 향상을 도모 / ~에 대한 이해를 높임 / 최소화하고자" → 동사로 (P1)
12. 계사·과시 동사 "~을 자랑합니다 / ~을 완비하고 있습니다 / ~을 제공합니다" 남발 (P1)
13. 영어병기·외래어 과용 "퀄리티 / 디테일 / 케어 / 솔루션 / 시스템" 무분별 (P2)
14. 동의어 순환(같은 말 바꿔 반복하며 분량 부풀리기) (P2)

### C. 문장 구조 / 리듬 (P0·P1)
15. **문장 길이 균일**(15~25자 또는 종결어미가 규칙적으로 반복) → 변주 필요 (P1)
16. 종결어미 4연속 동일 "~습니다. ~습니다. ~습니다. ~습니다." (P0)
17. 접속사 문두 남발(그리고/또한/그래서/하지만/따라서 연발) (P1)
18. "~뿐만 아니라 ~도" / "~는 물론 ~까지" 병렬 구문 과용 (P2)
19. 만연체(한 문장에 뜻 3개+ 우겨넣기) (P1)
20. 이중부정·수동태 겹침 "이용이 불가하지 않습니다" (P2, 심하면 dumbify가 최종 처리)

### D. 담화 / 진행 상투 (P1·P2)
21. 습관적 순서 표지 "먼저 / 다음으로 / 또한 / 마지막으로 / 끝으로" 기계적 배치 (P2)
22. 전이 상투 "그렇다면 / 그런데 말이죠 / 자, 그럼" 과다 (P2)
23. 독자 유도 상투 "한번 알아볼까요? / 함께 살펴보겠습니다 / ~해 보세요" (P1)
24. 과장 감탄 "놀랍게도 / 무려 / 실로 / 그야말로" (P1)
25. 가짜 공감 "~때문에 고민 많으시죠 / 다들 한 번쯤 겪어보셨을 겁니다" (P1)

### E. 시각·마크업 티 (P0·P1) — 한글 블로그 특유
26. 이모지 헤더/불릿("✨소제목✨", "👉 이렇게") 남발 (P0)
27. 과한 볼드(문장의 절반을 굵게) (P2)
28. 불필요한 불릿화(문장이면 될 걸 다 목록으로) (P1)
29. 해시태그 6개+ 나열 → 핵심 2~3개로 (P2)
30. 과한 말줄임표·물결(~~) / 느낌표 연타(!!!) (P2)

### F. 진정성 결핍 / AI 지문 (P0·P1)
31. 근거 없는 단정 "전문가들은 ~라고 합니다 / 많은 사람들이 ~합니다"(출처 없음) (P1)
32. 자리표시자 잔존 "[상호명] / [지역] / OO점" 치환 누락 (P0)
33. 확정 못하는 사실을 우물쭈물 "~인 것으로 보입니다 / ~일 수 있습니다" 반복(사실이면 단정) (P1)
34. AI 자기지칭·과공손 "제가 도와드리자면 / 좋은 질문입니다 / 함께 알아가요" (P0)
35. 정보 없이 분위기만("특별한 경험을 선사합니다 / 새로운 차원의") (P1)

> 6개 카테고리는 공개팩의 6카테고리(콘텐츠·어휘·구조·커뮤니케이션·메타·AI지문)에 1:1 대응하되,
> 항목 내용은 한국어 실사용 신호로 교체했다. 파이프라인 정착 후 실데이터로 항목을 계속 증분한다.

## 한글판 표현 교체 테이블 (발췌)

번역이 아니라 **한글 블로그에서 실제로 튀는 표현 → 자연스러운 대체**. 세 등급으로 관리한다.

**Tier 1 (거의 항상 교체)**
| AI티 표현 | 대체 방향 |
|---|---|
| ~할 수 있습니다 (반복) | 단정형("~한다/~된다") 또는 구체 동사 |
| ~을 자랑합니다 / 완비하고 있습니다 | ~이 있다 / ~을 갖췄다 |
| 다양한 / 여러 가지 | 개수·종류를 구체적으로("웨이트 기구 12종") |
| 효과적인 / 뛰어난 | 근거로 대체("대기 없이 바로 쓴다") |
| ~을 도모하고자 / 최소화하고자 | ~하려고 / ~을 줄이려고 |
| 소개해 드리려고 합니다 | (삭제, 바로 본론) |

**Tier 2 (문맥 보고 교체)**
| AI티 표현 | 대체 방향 |
|---|---|
| 정말 / 너무 / 매우 | 삭제하거나 정도를 사실로("3년째 다닌다") |
| ~라고 할 수 있습니다 | ~다 (단정) |
| 최적의 / 완벽한 | 조건 명시("아침 운동엔 6시 오픈이 맞다") |
| 특별한 경험 | 무엇이 특별한지 구체화 |

**Tier 3 (톤에 따라 허용)**
| AI티 표현 | 대체 방향 |
|---|---|
| 먼저 / 또한 / 마지막으로 | 필요한 1~2곳만 남김 |
| ~인 것 같습니다 | 사실이면 단정, 의견이면 유지 가능 |

> 이 테이블은 **초기 시드**다. 엔진 배선 후 실제 초안에서 반복 검출되는 표현을 계속 추가해 100개+로 키운다.

## 규칙

### DO
- 카탈로그·교체테이블 기준으로 1차 감지 → 재작성(rewrite 모드) → **2차 패스로 재작성본 자가감사**.
- 문장 길이를 사람처럼 변주한다(짧은 문장·긴 문장 섞기). 종결어미를 섞는다(~다/~죠/명사종결/의문).
- 남용 부사·막연 수식어는 삭제하거나 구체어로 바꾼다("정말 좋다" → "3년째 다니는 이유").
- 접속사는 꼭 필요한 논리 전환에만 남긴다.
- 공허한 일반론은 구체 수치·고유명사·감각 묘사로 대체한다(단, **없는 사실 생성 금지**).

### DON'T
- **storytelling이 넣은 '의도된 서사 접속사'(그런데/그래서 서사 축)를 무차별 삭제하지 않는다.**
  기계적 반복만 정리하고, 문단 사이 서사 연결 1~2개는 보존한다.
- 없는 사실·수치·수상·연혁을 새로 지어내 "구체화"하지 않는다(전역 0번 규칙).
- 상호·이미지 마커·소제목·확정 수치를 삭제하지 않는다.
- 격식을 페르소나 설정(`formality`) 밖으로 바꾸지 않는다(그건 voice-dna 담당).
- **리듬 다양화(패턴 15)가 storytelling의 서사 리듬과 충돌하지 않게** 한다 — storytelling이 만든
  긴장/해소 문단 흐름은 보존하고, '문장 길이 균일'만 변주한다(정합성은 storytelling.md §anti-ai 정합 참조).

## 적용 전후 예시

**전**
> 오늘은 강남 헬스장에 대해 알아보겠습니다. 요즘 같은 시대에 건강은 정말 중요합니다.
> 그리고 꾸준한 운동은 매우 좋습니다. 또한 다양한 기구를 이용할 수 있습니다.
> 이곳은 여러분에게 큰 도움이 될 수 있습니다.

**후**
> 저녁 8시, 러닝머신 20대가 거의 다 찼다. 강남 한복판에서 이 시간에 자리가 남는 헬스장은 드물다.
> 프리웨이트 존은 3층, 유산소는 2층으로 나뉘어 있어 붐비는 시간에도 동선이 엉키지 않는다.

**감지 로그 예시(detect 모드 출력)**
```
P0  A-1  상투 도입 "오늘은 ~알아보겠습니다"
P0  C-16 종결어미 4연속 "~중요합니다/~좋습니다/~있습니다/~있습니다"
P1  B-9  강조부사 "정말/매우"
P1  B-7  막연 수식어 "다양한"
P1  C-17 접속사 문두 "그리고/또한"
P1  A-5  호명 상투 "여러분에게"
→ 임계값 초과(P0 2, P1 4/3카테고리) → 문단 단위 재작성 승격
```

## 출력 4섹션 (rewrite 모드)

1. **발견된 이슈** — 심각도별 히트 목록(위 감지 로그 형식).
2. **재작성본** — `revisedMd`.
3. **바뀐 것** — `changes[]`(before/after/reason).
4. **2차 패스 자가감사** — 재작성본을 다시 스캔한 결과. 남은 P0/P1(이상적으로 0). 재교체분 반영.

## 통과 체크리스트

- [ ] 상투적 도입부·마무리 문구 0개(A-1·A-2 = P0).
- [ ] 강조 부사(정말/너무/진짜/매우/굉장히) 문단당 1개 이하.
- [ ] "~할 수 있습니다 / ~라고 할 수 있습니다" 반복 2회 이하.
- [ ] 문장 시작 접속사 연속 2문장 이하.
- [ ] 종결어미 3연속 동일 없음 + 문장 길이 변주 있음(C-15/16).
- [ ] 이모지 헤더·자리표시자 잔존 0개(E-26·F-32 = P0).
- [ ] 새로 생성된 사실·수치 0개(전역 0번 규칙 위반 없음).
- [ ] 이미지 마커·소제목·상호 보존.
- [ ] **2차 패스 통과**(재작성본 재스캔에서 P0/P1 잔존 0).

## 입출력 (엔진 배선)

```ts
// 입력
{ draftMd, persona, options?: {
    mode?: "rewrite" | "detect" | "edit";           // 기본 rewrite
    aggressiveness?: "light" | "normal" | "strong"; // 기본 normal
    keepNarrativeConnectors?: boolean;              // 기본 true(storytelling 뒤이면 필수 true)
    minSeverity?: "P0" | "P1" | "P2";               // detect 모드에서 보고 하한(기본 P1)
} }
// 출력
{ revisedMd,
  changes,                       // before/after/reason
  hits: { code: string; severity: "P0"|"P1"|"P2"; span: string }[], // 감지 로그(detect 필수)
  secondPass: { remaining: number; refixed: number },               // 2차 패스 결과
  notes?
}  // detect 모드는 revisedMd = draftMd 원본(무변경) + hits만 채움
```
