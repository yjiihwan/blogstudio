# storytelling — 서사 구조 부여

정보 나열식 문단을 '그런데/그래서'로 이어지는 **서사(내러티브)** 로 재배치한다.
독자가 다음 문단을 읽을 이유(긴장→해소)를 문단 사이에 심는다.

## 트리거 (언제 발동)

- 문단이 서로 독립된 정보 블록으로만 나열되어 인과·전환이 없을 때.
- "정의→장점→방법→마무리" 같은 틀이 섹션마다 반복될 때.
- 불릿·번호 목록이 문장으로 충분한 내용을 대체하고 있을 때.
- 파이프라인상 **초안 직후 첫 패스**(가장 큰 구조 변경을 먼저).

## 규칙

### DO
- 문단 사이에 서사 연결을 넣는다: **상황 → 그런데(긴장/반전) → 그래서(해소/행동)**.
- 도입에 구체적 장면·문제를, 중반에 전환을, 후반에 해소를 배치한다.
- 목록을 흐름이 있는 문장으로 풀어 쓴다(핵심만 목록 유지).
- 독자의 관점·궁금증을 다음 문단이 받아 답하게 연결한다.

### DON'T
- **서사 접속사('그런데/그래서/그러다')를 문단마다 기계적으로 붙이지 않는다.** 글 전체에서
  의미 있는 전환 지점 위주로 쓴다(남발은 뒤 anti-ai가 정리하지만, 처음부터 절제).
- 없는 사건·경험·에피소드를 지어내 서사를 만들지 않는다(전역 0번 규칙). 서사는 **확정 사실의
  재배열·감각 묘사·독자 관점**으로만 만든다.
- 소제목·이미지 마커의 위치를 서사 때문에 뒤섞어 문맥을 깨지 않는다.
- 억지 반전("놀랍게도")·과장 감탄으로 긴장을 만들지 않는다.

## anti-ai 리듬 다양화와의 정합 (충돌 방지)

storytelling은 **구조**(문단 간 긴장→해소 흐름)를, anti-ai(패턴 C-15)는 **문장 리듬**(문장 길이 균일 깨기)을
담당한다. 층위가 달라 원칙적으로 충돌하지 않지만, 아래를 지켜 뒤 단계와 정합을 맞춘다.

- storytelling은 서사를 만들되 **문장 길이를 처음부터 변주**한다(짧은 긴장 문장 + 긴 묘사 문장 섞기).
  이러면 anti-ai가 리듬을 다시 손댈 여지가 준다.
- '그런데/그래서' 서사 접속사는 **의미 있는 전환점 1~2곳만**. 남발하면 anti-ai(C-17 접속사 문두 남발)가
  걷어내다가 서사 축까지 지울 위험이 커진다. 절제가 곧 정합.
- 반대로 anti-ai는 storytelling의 **의도된 서사 접속사·긴장/해소 문단 흐름은 보존**한다(anti-ai DON'T 명시).
- 공개팩은 강한 storytelling 대응물이 없다 → 우리 **차별점**. 유지하되 위 정합만 지키면 anti-ai와 상호 보완.

## 적용 전후 예시

**전**
> 이 필라테스 센터는 기구 필라테스를 운영합니다. 강사는 전원 자격증을 보유합니다.
> 수업은 소규모로 진행됩니다. 주차가 가능합니다.

**후**
> 처음 기구 필라테스를 예약할 때 가장 걱정한 건 "혼자 못 따라가면 어쩌지"였다.
> 그런데 이곳은 한 타임 정원이 적어, 강사가 동작마다 자세를 잡아준다.
> 그래서 첫날부터 리포머 위에서 헤매지 않고 끝까지 따라갈 수 있었다.
> (차를 가져와도 부담이 없다 — 건물 주차가 된다.)

## 통과 체크리스트

- [ ] 도입에 구체적 장면/문제가 있다.
- [ ] 문단 사이 최소 1개 이상의 의미 있는 전환(그런데/그래서)이 있고, 남발(문단마다)은 아니다.
- [ ] 목록 남발이 문장 흐름으로 완화됐다.
- [ ] 새로 지어낸 사건·경험 0개(확정 사실 재배열만).
- [ ] 소제목·이미지 마커 위치·문맥 보존.

## 입출력 (엔진 배선)

```ts
// 입력
{ draftMd, persona, options?: {
    arc?: "problem_solution" | "before_after" | "journey"; // 기본 problem_solution
    maxConnectors?: number; // 서사 접속사 상한(기본: 문단수/3 정도)
} }
// 출력
{ revisedMd, changes, notes? }  // 공통 SkillResult
```
